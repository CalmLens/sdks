# @calmlens/sdk-go

## 1.0.0

### Major Changes

- f31404e: Follows the CalmLens API v1 contract:
  
  - `Assets.List` and `Assets.ListAll` request `GET /v1/projects/{projectId}/assets`.
  - `OrderAscending` and `OrderDescending` are lowercase: `"asc"` and `"desc"`.
  - API errors no longer carry `traceId` in `Details`. `RequestID` comes from the `X-Request-Id` header, or from the error body's `requestId`.
  - The generated `Code...` constants include the validation codes and the new route, internal, authentication, search, transform, remote URL, copyright and permission codes.
  - Webhook bodies use the same flat shape as `Events.List` items: `ParseWebhookEvent` and `VerifyWebhookRequest` return a `*Event`, and `ToWebhookEventPayload` returns an `Event` whose `Raw` is the body. `WebhookEventPayload` and `WebhookEventData` are removed.
  - `Event` no longer has `UserID`, `Notify`, `UpdatedAt` or `ReadAt`.
  - `Asset` no longer has `UserID`, and `AssetContent` no longer has `SafetyTest`.
  - `ListFoldersOptions` no longer has `SearchAll`, `IDs` or `ResolveOnly`, and `Folders.List` returns 50 folders by default.
  - The `calmlenstest` mock follows the same contract: its error bodies carry `requestId` and an object `details`, unknown routes fail with `misc/route-not-found`, invalid filters with `validation/invalid-filter`, and every cursor list defaults to 50 items.
- 7fa8620: `Lens` no longer includes `userId`.
- 64e9180: Asset reviews no longer include `reviewerUserId`, and hash lists and hash list entries no longer include `createdByUserId`.

### Minor Changes

- 2e04da8: Assets have `classification.failureReason`, which says why processing failed while `classification.status` is `failed` (such as `duration-limit` or `unsupported-format`), and is `null` otherwise. The `asset.failed` event carries the same value in its `failure-reason` fact. The in-memory mocks give a failed asset `processing-error`. The JavaScript SDK exports the `AssetClassificationFailureReason` type.
- e460921: Breaking: an asset's picture is one field, `content.image`, with `width`, `height`, `thumbhash`, `averageColor` and `perceptualHash`. It replaces `content.image` (size and perceptual hash) and `content.previewImage`. For images, the width and height are the original upload's. For documents and websites, they are the page image's. The JavaScript SDK exports the `AssetImage` type, which replaces `ImageData` and `PreviewImage`. `CalmLensMedia` sizes itself and shows its placeholder colour from `content.image`.
- 11d0d81: CDN URL builders take a `placeholder` resource: a small blurred PNG of the asset that the CDN serves publicly for every asset, private ones included, whatever its moderation status, for example in place of an age-restricted image. It takes no lens, transform or `ageConfirmed`, and passing one is rejected with `sdk/invalid-argument`, as is an unknown resource.
  
  The JavaScript SDK exports `getAssetUrl` from `@calmlens/sdk/app` and `@calmlens/sdk`. It builds the same CDN URLs as the server client's `cdn.getAssetUrl` from a project ID, with no API key and no request, so it works in browsers.
- 8cc1cae: Add `client.Assets.Batch(ctx, calmlens.BatchAssetsOptions{AssetIDs, Operation})`, which deletes up to 500 assets (`AssetBatchOperationDelete`) or removes their stored content (`AssetBatchOperationRemoveContent`) in one request and returns a `BatchAssetsResponse` with `Queued`. It sends `POST /projects/:projectId/assets/batch`. Every asset must exist in the project and the API key needs `assets:delete` for its folder, or the request fails (`asset/not-found`, `auth/permission-denied`) and nothing is queued; once queued, the work runs in the background and records `asset.deleted` or `asset.content-removed` for each asset. The method refuses an empty list, more than 500 IDs, an empty ID or an unknown operation with `sdk/invalid-argument` before sending, and is not retried. The new `auth/permission-denied` error code is available as a constant. `calmlenstest` validates the batch like the API and applies it at once,.
- 6232efc: The Go SDK now behaves like the other CalmLens SDKs in every shared contract case.
  
  - Requests send `Accept: application/json` (API calls) and `User-Agent: calmlens-go/<version> (go/<Go version>)`.
  - Retries wait between half and all of the exponential backoff, honour `Retry-After` in seconds or as an HTTP date (`0` retries at once), and `CDN.Serve` retries like an API read, returning the last response when retries run out. Redirects fail with `sdk/http-error` and the redirect's status, also from `CDN.Serve`.
  - `Error.RetryAfter` is a `*time.Duration`, nil without a `Retry-After` header. Transport failures have no `Details`, and API errors no longer add `network: true`.
  - `Options.UploadTimeout` bounds binary uploads (none by default); `Options.Timeout` now covers text uploads and URL submissions, and `CDN.Serve` until its headers arrive. A declared `Content-Length` over `MaxResponseBytes` fails before the body is read, and an upload answered with something other than an asset fails with `sdk/invalid-response`.
  - `client.WithRequestOptions(calmlens.RequestOptions{...})` returns a client with other deadlines or retries that shares the credentials and lens cache.
  - `WaitForDecisionOptions.Timeout` is a `*time.Duration`: nil waits the default 60 seconds and zero checks once. `ListFoldersOptions.SearchAll` and `ResolveOnly` are `*bool`, so an explicit `false` is sent.
  - Iterators fail with `sdk/invalid-response` (`Details["cursor"]`) when a page that says more follow repeats a cursor, and event pages with more to follow continue past empty pages. `EventIterator.NextPage` and `Page` read the feed a page at a time.
  - Webhooks: `VerifyWebhookHeaders` verifies against an `http.Header`; header names match in any case and repeated signature headers are joined; `WithTolerance(0)` accepts only the signing second; parsing checks the API's event shape and keeps the whole body in `WebhookEventPayload.Raw`, which `ToWebhookEventPayload` also fills. Upload tokens encode claims exactly as the server does.
  - `calmlenstest` adds `FailNextRequest`, `SetAPIKeyGrants` and `SignUploadToken`, and `EnqueueEvent` returns the stored events. The mock answers schema errors with `validation/<issue>` and `details.path`, scopes cursors to their query, records `asset.retried`, `asset.content-removed` and `asset.deleted` events, serves a ThumbHash placeholder PNG and the CDN's cache and protection headers, checks multipart image totals, multipart part sizes, idempotency key rules, lens versions and folder rules like the API. It reads an idempotency key without surrounding whitespace, as HTTP sends it.
- 58840e7: Adds `Assets.Decide(ctx, DecideAssetOptions{AssetID, Decision, Note, ConfirmPurge})`, which records a reviewer's decision with a note and returns the asset. Every list now pages with cursors: `ListFoldersOptions` takes `Cursor`, `PageSize` and `Ordering` (by `name` or `createdAt`) instead of `PageIndex`, `Sort` and `Direction`, and `FolderPage` returns `Items`, `Ancestors`, `NextCursor`, `HasMore`, `PageSize` and `Ordering`. `HashLists.List` takes `ListHashListsOptions{Cursor, PageSize}` and returns a `HashListPage`. `ListEventsOptions` takes `Cursor` and `PageSize` instead of `After` and `Limit`, and `EventsPage` returns `Items` and `NextCursor` instead of `Events` and `Cursor`. `CodeInvalidEventCursor` is removed: an unreadable events cursor is `CodeInvalidCursor`. The `calmlenstest` mock implements `Assets.Decide` with the API's validation and the new list shapes.
- 105ccc2: Adds the `limited` moderation status (`ModerationStatusLimited`, `ModerationDecisionLimited`), the `limit` policy action (`ModerationActionLimit`) and the `asset.limited` event (`EventAssetLimited`, with the same `AssetDecisionFacts` as the other decision events). A limited asset is delivered exactly like an allowed one, from the same URL, but is marked so your app can reduce its reach: keep it out of recommendations, trending and notifications, rank it lower or collapse it behind a "show" control. The mock accepts `calmlenstest.OutcomeLimited` for `QueuedOutcome`, `AnalyzedOutcome` and `Decide`, and its CDN serves limited assets like allowed ones.
- 958be0d: The `calmlenstest` mock's `CDN.Serve` now answers like the CDN: blocked, purged and failed assets, and assets whose content was removed, return `403` with `asset/not-available` whatever the key, before any permission check. `Decide(assetID, decision)` applies a reviewer's decision and adds the matching `asset.<decision>` event with a `decided-by: reviewer` fact. Waits take no real time: retry backoff and `Assets.WaitForDecision` only advance the mock client's clock, so a pending asset returns `sdk/timeout` straight away.
- 2b11c12: Breaking: an asset's moderation outcome is now `classification.moderation.status`: `pending`, then `allowed`, `age-restricted`, `blocked` or `purged`. It replaces `classification.moderation.decision` and `classification.moderation.action`, and filters use `classification.moderation.status`. Manual reviews record their `decision` as one of the four decided statuses and no longer have an `action`. Policy actions are `allow`, `age-restrict`, `block` and `purge`; `flag` is removed.
  
  Webhook and event types `asset.flagged`, `asset.approved` and `asset.rejected` are replaced by `asset.classified` and one event per status: `asset.allowed`, `asset.age-restricted`, `asset.blocked` and `asset.purged`. Event asset snapshots carry `classification.moderation.status`, and the `moderation-action` and `review-action` facts are replaced by `moderation-status` and `decided-by`.
  
  Waiting for a decision returns once the status is no longer `pending`. Mock clients take the new statuses as outcomes, and `purged` removes the content.
  
  CDN URL builders take an `ageConfirmed` option that adds `ageConfirmed=true`, so a public age-restricted asset can be served from its public URL where your app has already decided the viewer may see it. Without it, age-restricted assets need a signed URL or an API key.
- dd08099: CalmLens IDs now name the kind of object they identify: a prefix, an underscore and 20 letters and digits, such as `proj_8fK2mQx7Lp4NvB3tRz9Y` for a project, `asset_5Gm2Rk8XqT3wLp9VbN4c` for an asset and `fldr_7Nc4Wq2Lm8Xt5Rk9Bv3P` for a folder. The in-memory mocks mint IDs the same way, and their ID option (`createId`, `create_id` or `CreateID`) now receives the prefix of the object it names (`asset`, `fldr`, `hl`, `hle`, `lens`, `evt` or `rev`). The mocks' `assets.batch` refuses an ID that is not an asset ID with `validation/invalid-format`, as the API does.
- 454706c: Uploads and text classification take `authorId` and `context`: who wrote the content and the earlier posts of its conversation, oldest first, each with an optional author ID. CalmLens moderates only the content and uses the earlier posts to read who it addresses and whether it quotes, reports, counters or mocks something. The SDKs send only the posts CalmLens uses, the most recent 5 that fit in 2,000 characters, and export the rule that picks them. Assets return `authorId` and the `context` used, which is `null` once the content is removed. The offline mocks store both and drop the context with the content.
- 17cdb9b: CDN methods, signed URL creation and media widgets accept optional `viewerClaims` containing `region` and `ageConfirmed`. These replace the separate region and age options. The CDN defaults to the connecting country and no age confirmation, including authenticated requests. Customers determine the assertions; CalmLens applies content restrictions without independently verifying them.
  
  Asset retrieval returns stored moderation results without a request-specific `delivery` object or region parameter. Pass viewer context on the CDN request instead. Raw HTTP supports a JSON query parameter or `X-CalmLens-Viewer-Claims` header. Age-restricted delivery without confirmation returns `viewer/age-confirmation-required`; private access remains a separate requirement.
- 958be0d: New helpers build signed webhook deliveries for testing a webhook handler, as the JavaScript, Python and PHP SDKs already do. `CreateWebhookHeaders` (Go), `create_webhook_headers` (Rust), `CalmLens.create_webhook_headers` (Ruby) and `CalmLensServerClient.createWebhookHeaders` (Java) return the `content-type`, `x-calmlens-delivery`, `x-calmlens-timestamp` and `x-calmlens-signature` headers for a body. Ruby's `CalmLens.to_webhook_event_payload` and Java's `CalmLensServerClient.toWebhookEventPayload` convert an event from `events.list` to its delivery body.

### Patch Changes

- 6d65133: Event facts' `url` is now a stable link that opens the item in the CalmLens portal, such as `https://calmlens.com/go/asset/<asset-id>`, in webhook payloads and the events feed. The in-memory mocks give asset facts the same links.
- 91cd4a1: The `calmlenstest` mock answers with the HTTP statuses the API sends: `201 Created` for `Folders.Create` and `202 Accepted` for `Assets.Batch` (it answered `200` for both).
- 92bf5db: The `calmlenstest` mock's `Assets.Search` now works like the API's keyword search: every query word (case-insensitive, up to 8) must appear in the name, ID, external ID, description, tags, type, content format or extension, or moderation status, and results are ranked by the API's score, then newest first. List cursors resume after the last returned asset, so assets created or deleted between pages don't shift later pages. The default mock clock advances at least 1 ms per reading, so assets created in a row have increasing `createdAt` values; a `Now` you supply is used as is.
- e4e9894: `CalmLensMedia` shows the CDN placeholder for private assets and signed URLs too, since the CDN serves every asset's placeholder publicly. It sends only viewer claims that differ from the defaults (a `region`, or `ageConfirmed: true`), so `ageConfirmed: false` no longer makes the CDN's responses private and uncacheable, and placeholder URLs carry only the region. The mock clients serve private assets' placeholders without `assets:download`, as the CDN does.
- 1e59923: The mock clients' `cdn.serve` now sends `Cache-Control` as the CDN does: `public` only when anyone may see the asset (including a public age-restricted asset requested with `ageConfirmed`), otherwise `private`, with `max-age=31536000, immutable` for images and `max-age=3600` for other content. JavaScript and Python previously sent `private, no-store` or `public, max-age=31536000`; Go and Ruby sent no `Cache-Control`.
- e4e9894: The mock clients accept the real client's upload timeout and response size limit: `upload_timeout` and `max_response_bytes` on Python's `MockCalmLensServerClient`, `UploadTimeout` and `MaxResponseBytes` on Go's `calmlenstest.Options`, `uploadTimeout` and `maxResponseBytes` on PHP's `MockServerClient`, and `MockOptions::upload_timeout` and `MockOptions::max_response_bytes` in Rust. They are validated like the real client's, and the size limit applies to the mock's answers.
- 958be0d: Creating a signed URL now fails with `sdk/invalid-argument` before sending anything when the API would reject it: a resource other than `original` or `rendered` (a placeholder needs no signed URL), a lens or transform on the `original` resource, or a lifetime that is not a whole number of seconds from 1 to 86400 (24 hours). The longest lifetime is available as `MAX_SIGNED_URL_SECONDS` in Rust and Java, `MaxSignedURLSeconds` in Go, `CalmLens::Assets::MAX_SIGNED_URL_SECONDS` in Ruby and `CalmLens\Assets::MAX_SIGNED_URL_SECONDS` in PHP.
