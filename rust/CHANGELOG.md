# @calmlens/sdk-rust

## 1.0.0

### Major Changes

- 7fa8620: `Lens` no longer includes `userId`.
- 64e9180: Asset reviews no longer include `reviewerUserId`, and hash lists and hash list entries no longer include `createdByUserId`.
- cf3f682: Follows the CalmLens API v1 contract:
  
  - `assets().list` and `assets().iterate` request `GET /v1/projects/{projectId}/assets`.
  - `SortDirection::Asc` and `SortDirection::Desc` are sent and read as `asc` and `desc`.
  - API errors no longer copy `traceId` into `details()`. `request_id()` is the `X-Request-Id` header, or the error body's `requestId` when the header is missing.
  - `ErrorCode` includes the validation codes and the new route, internal, authentication, search, transform, remote URL, copyright and permission codes.
  - `WebhookEventPayload` has the same flat shape as an `Event` from `events().list`: `severity`, `title`, `description`, `asset_id`, `asset` and `facts` are top-level fields, and `WebhookEventData` is removed. `parse_webhook_event`, `construct_webhook_event` and `WebhookEventPayload::from_event` read and write that shape.
  - `Event` no longer has `user_id`, `notify`, `updated_at` or `read_at`.
  - `Asset` no longer has `user_id`, and `AssetContent` no longer has `safety_test`.
  - `ListFolders` no longer has `search_all`, `ids` or `resolve_only`, and folders list 50 to a page by default.
  - The testing mocks follow the same contract: error bodies carry `requestId`, and every cursor list defaults to 50 items.

### Minor Changes

- 2e04da8: Assets have `classification.failureReason`, which says why processing failed while `classification.status` is `failed` (such as `duration-limit` or `unsupported-format`), and is `null` otherwise. The `asset.failed` event carries the same value in its `failure-reason` fact. The in-memory mocks give a failed asset `processing-error`. The JavaScript SDK exports the `AssetClassificationFailureReason` type.
- e460921: Breaking: an asset's picture is one field, `content.image`, with `width`, `height`, `thumbhash`, `averageColor` and `perceptualHash`. It replaces `content.image` (size and perceptual hash) and `content.previewImage`. For images, the width and height are the original upload's. For documents and websites, they are the page image's. The JavaScript SDK exports the `AssetImage` type, which replaces `ImageData` and `PreviewImage`. `CalmLensMedia` sizes itself and shows its placeholder colour from `content.image`.
- 11d0d81: CDN URL builders take a `placeholder` resource: a small blurred PNG of the asset that the CDN serves publicly for every asset, private ones included, whatever its moderation status, for example in place of an age-restricted image. It takes no lens, transform or `ageConfirmed`, and passing one is rejected with `sdk/invalid-argument`, as is an unknown resource.
  
  The JavaScript SDK exports `getAssetUrl` from `@calmlens/sdk/app` and `@calmlens/sdk`. It builds the same CDN URLs as the server client's `cdn.getAssetUrl` from a project ID, with no API key and no request, so it works in browsers.
- 2b11c12: Breaking: an asset's moderation outcome is now `classification.moderation.status`: `pending`, then `allowed`, `age-restricted`, `blocked` or `purged`. It replaces `classification.moderation.decision` and `classification.moderation.action`, and filters use `classification.moderation.status`. Manual reviews record their `decision` as one of the four decided statuses and no longer have an `action`. Policy actions are `allow`, `age-restrict`, `block` and `purge`; `flag` is removed.
  
  Webhook and event types `asset.flagged`, `asset.approved` and `asset.rejected` are replaced by `asset.classified` and one event per status: `asset.allowed`, `asset.age-restricted`, `asset.blocked` and `asset.purged`. Event asset snapshots carry `classification.moderation.status`, and the `moderation-action` and `review-action` facts are replaced by `moderation-status` and `decided-by`.
  
  Waiting for a decision returns once the status is no longer `pending`. Mock clients take the new statuses as outcomes, and `purged` removes the content.
  
  CDN URL builders take an `ageConfirmed` option that adds `ageConfirmed=true`, so a public age-restricted asset can be served from its public URL where your app has already decided the viewer may see it. Without it, age-restricted assets need a signed URL or an API key.
- dd08099: CalmLens IDs now name the kind of object they identify: a prefix, an underscore and 20 letters and digits, such as `proj_8fK2mQx7Lp4NvB3tRz9Y` for a project, `asset_5Gm2Rk8XqT3wLp9VbN4c` for an asset and `fldr_7Nc4Wq2Lm8Xt5Rk9Bv3P` for a folder. The in-memory mocks mint IDs the same way, and their ID option (`createId`, `create_id` or `CreateID`) now receives the prefix of the object it names (`asset`, `fldr`, `hl`, `hle`, `lens`, `evt` or `rev`). The mocks' `assets.batch` refuses an ID that is not an asset ID with `validation/invalid-format`, as the API does.
- 8cc1cae: Add `client.assets().batch(BatchAssets { asset_ids, operation })`, which deletes up to 500 assets (`AssetBatchOperation::Delete`) or removes their stored content (`AssetBatchOperation::RemoveContent`) in one request and returns a `BatchAssetsResponse` with `queued`, in the async and blocking clients. It sends `POST /projects/:projectId/assets/batch`. Every asset must exist in the project and the API key needs `assets:delete` for its folder, or the request fails (`asset/not-found`, `auth/permission-denied`) and nothing is queued; once queued, the work runs in the background and records `asset.deleted` or `asset.content-removed` for each asset. The method refuses an empty list, more than 500 IDs or an empty ID with `sdk/invalid-argument` before sending, and is not retried. The new `auth/permission-denied` error code is available as a constant. The in-memory mock validates the batch like the API and applies it at once.
- 58840e7: Adds `assets().decide(DecideAsset::new(asset_id, decision, note))`, which records a reviewer's decision with a note and returns the asset (set `confirm_purge` to purge). Every list now pages with cursors: `ListFolders` takes `cursor`, `page_size` and `ordering` (by `name` or `createdAt`) instead of `page_index`, `sort` and `direction`, and `FolderPage` returns `items`, `ancestors`, `next_cursor`, `has_more`, `page_size` and `ordering`. `hash_lists().list(ListHashLists)` returns a `HashListPage`. `ListEvents` takes `cursor` and `page_size` instead of `after` and `limit`, and `EventsPage` returns `items` and `next_cursor` instead of `events` and `cursor`. `ErrorCode::InvalidEventCursor` is removed: an unreadable events cursor is `ErrorCode::InvalidCursor`. The in-memory mock implements `assets().decide` with the API's validation and the new list shapes.
- 6ee266e: `MockServerClient::in_memory` adds an in-memory API to the Rust mock, matching the other SDKs' testing support. Uploads create stored assets with a chosen `MockOutcome` (`queued_outcome` for `create`, `analyzed_outcome` for `classify`), and assets, folders, search, lenses, the events feed and CDN downloads behave like the API, including its error codes, idempotent replays and download permissions (`create_mock_api_key`). `decide` applies a reviewer decision and adds the matching `asset.<status>` event, and `enqueue_event` adds events to the feed. Queued responses are still used first.
- 105ccc2: Adds the `limited` moderation status and reviewer decision (`AssetModerationStatus::Limited`, `AssetModerationDecision::Limited`), the `limit` policy action (`FlaggedContentAction::Limit`) and the `asset.limited` event (`EventType::AssetLimited`). A limited asset is delivered like an allowed one, from the same URL, but marked so your app can reduce its reach, such as keeping it out of recommendations, trending and notifications, ranking it lower or collapsing it. The in-memory mock accepts `MockOutcome::Limited`, serves limited assets like allowed ones, and `decide` with `limited` adds an `asset.limited` event with `low` severity.
- 91cd4a1: The in-memory `MockServerClient` answers with the HTTP statuses the API sends: `201 Created` for `folders().create` and `202 Accepted` for `assets().batch` (it answered `200` for both). Captured requests now carry `response_status`, the status the mock answered with (`None` when the request failed without a response).
- 958be0d: `MockServerClient` waits take no real time: retry backoff and `assets().wait_for_decision` advance a virtual clock, read with `mock.elapsed()`, so a pending asset fails with `sdk/timeout` at once. The in-memory CDN now answers like the real one: blocked, purged and failed assets, and assets whose content was removed or is still uploading, return `403` with `asset/not-available` whatever the key, before any permission check (missing content previously returned `404`). `decide` gives its event the event catalog's severity: `low` for `allowed`, `high` otherwise. `MockOptions::api_base_url` and `MockOptions::cdn_base_url` set the URLs the mock answers.
- 6232efc: The client now matches the other CalmLens SDKs request for request:
  
  - API calls have a 120-second timeout by default, and binary uploads have none unless you set `upload_timeout`; text uploads keep the API timeout, and `cdn().serve`'s timeout ends when the response headers arrive. `max_response_bytes` (32 MiB by default) limits API response bodies, checking a declared `Content-Length` before reading. The defaults are exported as constants.
  - Retries wait half the backoff plus a random part of it, honour `Retry-After` given as an HTTP date, and retry a `Retry-After: 0` at once. Redirects fail with `sdk/http-error`, `cdn().serve` included, and `cdn().serve` returns the last response once its retries run out.
  - `assets().iterate`, `assets().iterate_children` and `events().pages` fail with `sdk/invalid-response`, naming the `cursor`, instead of repeating pages when a page hands back a cursor they already sent.
  - Concurrent `ensure_lenses` calls for the same definitions send them once.
  - `Content::unsized_stream` uploads a stream of unknown length. Later multipart parts are sent without a `Content-Type`.
  - `construct_webhook_event` reads repeated signature headers joined, and parsing requires a string `projectId`, a numeric `createdAt` and the API's types for known fields. `WebhookEventPayload::json()` returns the body as received, `WebhookEventPayload::is_test()` tells test sends apart, `verify_webhook_headers` verifies from an `http::HeaderMap`, and `EventAsset` keeps every snapshot field behind accessors such as `moderation_status()`.
  - Transport errors no longer carry a `network` detail, API calls send `Accept: application/json`, and the `User-Agent` is `calmlens-rust/<version> (rustc/<compiler version>)`.
  - The mock follows the API more closely: validation errors with the field's `path`, scoped list cursors, `asset.retried`, `asset.content-removed` and `asset.deleted` events, ThumbHash placeholders and the CDN's headers (byte ranges are gone, as the CDN has none), multipart and idempotency-key rules (a key is read without surrounding whitespace, as HTTP sends it), folder and lens error details, and lenses saved in order. Captured requests show the API key sent. `fail_next_request`, `set_api_key_grants`, `queued_outcome_for`/`analyzed_outcome_for`, `enqueue_hang`, `sleeps()` and `testing::sign_upload_token` for exact test tokens are new.
- ab0fcfa: Breaking: `SignedUrlOptions.resource` is a `SignedUrlResource` (`Original` or `Rendered`) instead of a `CdnResource`, so a signed URL can no longer be requested for the `placeholder` resource, which the API refuses.
- 454706c: Uploads and text classification take `authorId` and `context`: who wrote the content and the earlier posts of its conversation, oldest first, each with an optional author ID. CalmLens moderates only the content and uses the earlier posts to read who it addresses and whether it quotes, reports, counters or mocks something. The SDKs send only the posts CalmLens uses, the most recent 5 that fit in 2,000 characters, and export the rule that picks them. Assets return `authorId` and the `context` used, which is `null` once the content is removed. The offline mocks store both and drop the context with the content.
- 17cdb9b: CDN methods, signed URL creation and media widgets accept optional `viewerClaims` containing `region` and `ageConfirmed`. These replace the separate region and age options. The CDN defaults to the connecting country and no age confirmation, including authenticated requests. Customers determine the assertions; CalmLens applies content restrictions without independently verifying them.
  
  Asset retrieval returns stored moderation results without a request-specific `delivery` object or region parameter. Pass viewer context on the CDN request instead. Raw HTTP supports a JSON query parameter or `X-CalmLens-Viewer-Claims` header. Age-restricted delivery without confirmation returns `viewer/age-confirmation-required`; private access remains a separate requirement.
- 958be0d: New helpers build signed webhook deliveries for testing a webhook handler, as the JavaScript, Python and PHP SDKs already do. `CreateWebhookHeaders` (Go), `create_webhook_headers` (Rust), `CalmLens.create_webhook_headers` (Ruby) and `CalmLensServerClient.createWebhookHeaders` (Java) return the `content-type`, `x-calmlens-delivery`, `x-calmlens-timestamp` and `x-calmlens-signature` headers for a body. Ruby's `CalmLens.to_webhook_event_payload` and Java's `CalmLensServerClient.toWebhookEventPayload` convert an event from `events.list` to its delivery body.

### Patch Changes

- 6d65133: Event facts' `url` is now a stable link that opens the item in the CalmLens portal, such as `https://calmlens.com/go/asset/<asset-id>`, in webhook payloads and the events feed. The in-memory mocks give asset facts the same links.
- e4e9894: `CalmLensMedia` shows the CDN placeholder for private assets and signed URLs too, since the CDN serves every asset's placeholder publicly. It sends only viewer claims that differ from the defaults (a `region`, or `ageConfirmed: true`), so `ageConfirmed: false` no longer makes the CDN's responses private and uncacheable, and placeholder URLs carry only the region. The mock clients serve private assets' placeholders without `assets:download`, as the CDN does.
- 1e59923: The mock clients' `cdn.serve` now sends `Cache-Control` as the CDN does: `public` only when anyone may see the asset (including a public age-restricted asset requested with `ageConfirmed`), otherwise `private`, with `max-age=31536000, immutable` for images and `max-age=3600` for other content. They previously sent `private, no-store` or `public, max-age=31536000`. PHP's `MockServerClient::decide` now also records the review in the asset's `manualReviews`, as the Rust and Java mocks already did.
- e4e9894: The mock clients accept the real client's upload timeout and response size limit: `upload_timeout` and `max_response_bytes` on Python's `MockCalmLensServerClient`, `UploadTimeout` and `MaxResponseBytes` on Go's `calmlenstest.Options`, `uploadTimeout` and `maxResponseBytes` on PHP's `MockServerClient`, and `MockOptions::upload_timeout` and `MockOptions::max_response_bytes` in Rust. They are validated like the real client's, and the size limit applies to the mock's answers.
- 92bf5db: The in-memory `MockServerClient` keyword search matches every word of the query in any searchable field (now including type, content format and extension, and moderation status) and returns the API's keyword scores, matched fields and ranking. Mock list filters accept parentheses, with `;` binding tighter than `,`. The default mock clock gives assets created in a row increasing `created_at`, so lists, cursors and search order them predictably.
- 958be0d: Creating a signed URL now fails with `sdk/invalid-argument` before sending anything when the API would reject it: a resource other than `original` or `rendered` (a placeholder needs no signed URL), a lens or transform on the `original` resource, or a lifetime that is not a whole number of seconds from 1 to 86400 (24 hours). The longest lifetime is available as `MAX_SIGNED_URL_SECONDS` in Rust and Java, `MaxSignedURLSeconds` in Go, `CalmLens::Assets::MAX_SIGNED_URL_SECONDS` in Ruby and `CalmLens\Assets::MAX_SIGNED_URL_SECONDS` in PHP.
