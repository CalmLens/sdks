## 0.24.0

### Minor Changes

## 0.23.0

### Minor Changes

- `AssetContent::hls` now has `status`, `reason` and `renditions`: it says whether a requested adaptive stream is `preparing` or `ready`, or `unavailable` with a reason (`allowance-used`, `billing-required`, `spend-limit`, `processing-failed` or `content-not-kept`), and lists its renditions once ready. Check `status` rather than whether `hls` is `None`. The offline mock prepares no stream, so it reports `null`. This replaces the separate HLS status field added in 0.22.0.
- 30e0480: `LensDefinition::active` is now `Option<bool>`, left out of the request when `None`: the API defaults it to `true`, and `ensure_lens` treats `None` and `Some(true)` as the same definition. This is a breaking change for code that sets `active: true`, which becomes `active: Some(true)`.

  Building a client now fails with `sdk/invalid-config` for an API key that can't be sent as a header (spaces, line breaks or anything outside printable ASCII). Any other key format is left for the API to check.

  `MockServerClient::in_memory` now matches production on these points:
  - `fetch_cdn` of a private asset without a grant answers 404 `asset/not-found` whatever the asset's state, for every resource but its public placeholder. `cdn().serve` with the API key is unchanged.
  - Each `classification.moderation.categories` result reports `source` and `settings`.
  - An upload with an API key that names `upload_preset_id` takes the preset's folder, visibility and processing options, and is refused by its limits with `upload-preset/not-found`, `upload-preset/disabled`, `upload-preset/field-not-allowed`, `upload/unsupported-type` or `upload/too-large`. An upload that names a preset must now use one stored with `upload_presets().ensure`.
  - A lens defined without `active` is stored as active.

  `MockDecision::pending_review(reason, uncertain_categories)` leaves a decided asset waiting for human review. `mock.decide` clears it and `assets().decide` leaves it.

  `TestInputPreset::Germany` now has no instances and blocks delivery in `DE`. The `hate.regional-symbol` signal still carries the hate instance. `MockServerClient`'s captured `Request` now leaves the API key out of its `Debug` output.
- 928edde: Image transform options list only what the CDN accepts, and any other option fails locally with `sdk/invalid-argument`.

### Patch Changes

- c3bee2b: Adds the `sexual-artistic` qualifier, for sexual content that is art not made to arouse.

## 0.22.0

### Minor Changes

- d4f47e9: Events can report the new `configurator` role, and `auth/permission-denied` errors carry `details.role`, the least role that includes the permission in `details.permission`.
- 1c0eef1: An asset's `classification.moderation` names the policy that made the automated decision (`policy`: its `id`, its `revision` then and the `preset` release it used) and says when a human review is waiting (`pendingReview`: `requestedAt`, `reason` and `uncertainCategories`, `null` when none is waiting). A category's allowance or restriction `source` carries the `conditionScore` that triggered its rules, since a rule assessed as a whole can leave its qualifiers out of `raw`. A document or website decided by its parts lists the categories that decided it in `flaggedCategories`. The mocks keep no policies or review queue, so both new fields stay `null` in them.
- 008473f: Declare a project's configuration in code. `upload_presets()` lists, iterates and deletes upload presets, and `ensure` creates or replaces them by key; `project_settings()` gets and replaces the project's settings; `metadata_fields()` lists its metadata fields, `ensure` creates or replaces them by ID, and `delete` removes one. Send the `revision` you read to refuse a change made since. The blocking client offers the same methods, and `MockServerClient::in_memory` serves them.
- 11fd85b: `AssetContent::hls_status` says whether a requested adaptive stream is `preparing` or `ready`, or `unavailable` with a reason (`allowance-used`, `billing-required`, `spend-limit`, `processing-failed` or `content-not-kept`). The offline mock prepares no stream, so it reports `null`. Adds the `media/duration-limit` error code: audio or video whose file states it is over the duration limit is refused at upload, with `details.durationSeconds` and `details.limitSeconds`.
- 52cfb90: Errors raised by the SDK itself, with no HTTP response, report `error.is_local()` as `true`. That covers invalid arguments and options, content checked before it is sent (such as `ErrorCode::UnsupportedUploadType` for an unsupported type), timeouts and connection failures. They carry the code the API would use, with `status()` and `request_id()` returning `None`, so branch on `code()`.
- 1d9a0d0: Uploads no longer put asset fields in the URL. Text is sent as a JSON body, and files and first multipart parts as a `multipart/form-data` upload form: the name, description, metadata, tags, author, conversation context, external IDs, folder, upload preset and processing options go in its `options` part and the bytes in its `file` part, so none of them appear in proxy, CDN or server logs. The query string holds only `wait`, `contentType`, sizes and part numbers. The offline mock reads uploads the same way and refuses asset fields in a query string with `upload/options-in-query`, as the API does.

### Patch Changes

- Every project recognises its test inputs: the project setting that turned them on is gone, so test codes and test images made with the current signed format are always recognised. Nothing changes in how you generate or detect them.

## 0.20.0

### Minor Changes

- e1b32c3: Structured transform options are checked against the image transform schema before a CDN or signed URL is built: an unknown option (such as the earlier `{ type: "imageTransform", options: { ... } }` shape) or an invalid value (such as `width: 0` or `format: "bmp"`) fails with `sdk/invalid-argument`, naming each option, instead of building a URL the CDN refuses. Selector strings are passed to the CDN unchanged.

  Every SDK refuses an upload whose type CalmLens can't moderate (anything other than an image, audio, video, text, document or web page, such as `application/zip`) with `upload/invalid-mime-type` before sending it, as the API does.

  An option given as `null` (`None` in Python, `nil` in Ruby) is left out of the request, as if omitted, unless the API takes `null` for it, such as `description` to clear it or `folderId` for the project root.
