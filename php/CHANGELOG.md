# @calmlens/sdk-php

## 1.0.0

### Major Changes

- 7fa8620: `Lens` no longer includes `userId`.
- d15b170: Follows the CalmLens API v1 contract:
  
  - `assets->list` and `assets->each` request `GET /v1/projects/{projectId}/assets`.
  - Sort directions in `ordering` are lowercase: `asc` and `desc`.
  - API errors no longer carry `traceId` in `details`. `requestId` comes from the `X-Request-Id` header, or from the error body's `requestId`. `details` is the body's object as sent.
  - `ErrorCodes` includes the validation codes and the new route, internal, authentication, search, transform, remote URL, copyright and permission codes.
  - Webhook bodies and `Webhooks::toPayload` use the same flat shape as `events->list` items: `id`, `projectId`, `type`, `severity`, `title`, `description`, `assetId`, `asset`, `facts` and `createdAt`, without a `data` envelope. `Webhooks::parseEvent` and `Webhooks::isTest` read that shape.
  - Listed events no longer include `userId`, `notify`, `updatedAt` or `readAt`; `description`, `assetId` and `asset` are `null` when absent.
  - Assets no longer include `userId` or `content.safetyTest`. The person, face and AI-generated detection results are not part of the asset while those features are off.
  - `folders->list` no longer takes `searchAll`, `ids` or `resolveOnly`, and returns 50 folders by default.
  - `MockServerClient` follows the same contract: error bodies carry `requestId` and a `details` object, and every cursor list defaults to 50 items.
- 64e9180: Asset reviews no longer include `reviewerUserId`, and hash lists and hash list entries no longer include `createdByUserId`.

### Minor Changes

- 2e04da8: Assets have `classification.failureReason`, which says why processing failed while `classification.status` is `failed` (such as `duration-limit` or `unsupported-format`), and is `null` otherwise. The `asset.failed` event carries the same value in its `failure-reason` fact. The in-memory mocks give a failed asset `processing-error`. The JavaScript SDK exports the `AssetClassificationFailureReason` type.
- 8cc1cae: Add `$client->assets->batch(['assetIds' => [...], 'operation' => ...])`, which deletes up to 500 assets (`Assets::BATCH_DELETE`) or removes their stored content (`Assets::BATCH_REMOVE_CONTENT`) in one request and returns `['queued' => true]`. It sends `POST /projects/:projectId/assets/batch`. Every asset must exist in the project and the API key needs `assets:delete` for its folder, or the request fails (`asset/not-found`, `auth/permission-denied`) and nothing is queued; once queued, the work runs in the background and records `asset.deleted` or `asset.content-removed` for each asset. The method refuses an empty list, more than 500 IDs, an empty ID or an unknown operation with `sdk/invalid-argument` before sending, and is not retried. The new `auth/permission-denied` error code is available as a constant. `MockServerClient` validates the batch like the API and applies it at once.
- 58840e7: Adds `assets->decide(['assetId' => ..., 'decision' => ..., 'note' => ...])`, with `'confirmPurge' => true` for purges, which records a reviewer's decision with a note and returns the asset. Every list now pages with cursors: `folders->list` takes `cursor`, `pageSize` and `ordering` (by `name` or `createdAt`) instead of `pageIndex`, `sort` and `direction`, and returns `items`, `ancestors`, `nextCursor`, `hasMore`, `pageSize` and `ordering`. `hashLists->list` takes `cursor` and `pageSize` and returns one page. `events->list` and `eachPage` take `cursor` and `pageSize` instead of `after` and `limit`, and pages return `items` and `nextCursor`. `ErrorCodes::INVALID_EVENT_CURSOR` is removed: an unreadable events cursor is `INVALID_CURSOR`. `MockServerClient` implements `assets->decide` with the API's validation and the new list shapes.
- c4c3a79: Assets have a new moderation status, `limited`, decided by the new `limit` policy action, which ranks between `allow` and `age-restrict`. A limited asset is delivered exactly like an allowed one, from the same public URL without a signed URL or `ageConfirmed`; it is marked so your app can reduce its reach, such as keeping it out of recommendations, trending and notifications, ranking it lower or collapsing it. Webhooks and events add `asset.limited`, with the same facts as `asset.allowed`. `waitForDecision` treats `limited` as a decision, and `MockServerClient` accepts `limited` as an outcome and in `decide`, which adds an `asset.limited` event with severity `low`.
- 958be0d: `MockServerClient`'s CDN now answers like the real one: blocked, purged and failed assets, and assets whose content was removed or is still uploading, return `403` with `asset/not-available` whatever the key, before any permission check. The default key has no grants, like a real key without `assets:download`, so private assets and public age-restricted ones requested without `ageConfirmed` return `403` with `asset/api-key-missing-permission`; pass `apiKey: MockServerClient::createApiKey($grants)` with an `assets:download` grant to read them. The `downloadPermission` option is removed. `decide` gives its event the event catalog's severity: `low` for `allowed`, `high` otherwise.
- 01eaedf: Errors now use typed classes in `CalmLens\Exception` (`NotFoundException`, `RateLimitException`, `ConnectionException`, `TimeoutException`, `InvalidArgumentException`, `ConfigurationException`, `WebhookVerificationException` and others), all extending `CalmLensException`. Exceptions carry `requestId`, the underlying exception in `getPrevious()`, and `retryAfter()`, `isNotFound()` and `header()` helpers. `CalmLens\ErrorCodes` lists the API's error codes with their HTTP statuses, and `CalmLens\SdkErrorCodes` the SDK's own. A response larger than 32 MiB now fails with `sdk/response-too-large`.
  
  Webhooks gain `Webhooks::createHeaders` and `Webhooks::toPayload` for testing receivers, `SIGNATURE_TOLERANCE_SECONDS`, and a `headers` argument to `verify` and `parseEvent` that reads the signature and timestamp from request headers or `$_SERVER`.
  
  `MockServerClient` now emulates folders, search, child listings, multipart uploads, idempotency keys and RSQL filters with `,`, wildcards and value lists. `failNextRequest` simulates connection failures, timeouts and API errors, `createApiKey` builds keys whose grants decide CDN downloads, `maxRetries` enables retries, and waits advance a virtual clock instead of sleeping.
- c4c3a79: `ServerClient` takes `maxResponseBytes` (32 MiB by default) and `uploadTimeout` (seconds per binary upload attempt; none by default), also accepted in `requestOptions`, and its defaults are constants on `ServerClient`. A response whose declared `Content-Length` exceeds `maxResponseBytes` fails with `sdk/response-too-large` before its body is read. Retries now wait half the exponential backoff plus a random part of the other half; `Retry-After: 0` retries at once, `cdn->serve` retries like other reads and returns the last response, and timeouts are retried. A redirect fails with `sdk/http-error`, its status and request ID, `cdn->serve` included, and is never followed or retried. Transport errors no longer carry `details['network']`, and API errors carry only the API's details and `traceId`. Uploads answered with something other than an asset fail with `sdk/invalid-response`. A non-seekable file stream may leave out `sizeInBytes`. The API, not the client, now checks idempotency key characters, so those failures carry the API's code and status; like every HTTP request, a key is sent without surrounding whitespace. `assets->each`, `eachChild` and `events->eachPage` stop at an empty asset page and fail with `sdk/invalid-response` (with `details['cursor']`) without yielding a page that repeats a cursor already sent. `waitForDecision` polls with the client's usual retries and request deadline. Webhook helpers join repeated signature headers with `,`, and `parseEvent` checks the types of known `data` fields. The User-Agent now names the PHP runtime. `MockServerClient` adds `setApiKeyGrants`, `signUploadToken` for exact tokens at a fixed clock and nonce, and `failNextRequest` with an API error code and a client method to target; it records `asset.deleted`, `asset.content-removed` and `asset.retried` events, serves a ThumbHash placeholder PNG for classified images, sets the CDN's `Cache-Tag`, protection headers, `ETag` and `Expires`, returns `null` for unset fields, checks multipart parts in the API's order, scopes list cursors to their query, and refuses out-of-range page sizes, search limits and event limits with `validation/*` codes and `details['path']`. A reviewer's purge removes the content with reason `requested`.
- dd08099: CalmLens IDs now name the kind of object they identify: a prefix, an underscore and 20 letters and digits, such as `proj_8fK2mQx7Lp4NvB3tRz9Y` for a project, `asset_5Gm2Rk8XqT3wLp9VbN4c` for an asset and `fldr_7Nc4Wq2Lm8Xt5Rk9Bv3P` for a folder. The in-memory mocks mint IDs the same way, and their ID option (`createId`, `create_id` or `CreateID`) now receives the prefix of the object it names (`asset`, `fldr`, `hl`, `hle`, `lens`, `evt` or `rev`). The mocks' `assets.batch` refuses an ID that is not an asset ID with `validation/invalid-format`, as the API does.
- 454706c: Uploads and text classification take `authorId` and `context`: who wrote the content and the earlier posts of its conversation, oldest first, each with an optional author ID. CalmLens moderates only the content and uses the earlier posts to read who it addresses and whether it quotes, reports, counters or mocks something. The SDKs send only the posts CalmLens uses, the most recent 5 that fit in 2,000 characters, and export the rule that picks them. Assets return `authorId` and the `context` used, which is `null` once the content is removed. The offline mocks store both and drop the context with the content.
- 17cdb9b: CDN methods, signed URL creation and media widgets accept optional `viewerClaims` containing `region` and `ageConfirmed`. These replace the separate region and age options. The CDN defaults to the connecting country and no age confirmation, including authenticated requests. Customers determine the assertions; CalmLens applies content restrictions without independently verifying them.
  
  Asset retrieval returns stored moderation results without a request-specific `delivery` object or region parameter. Pass viewer context on the CDN request instead. Raw HTTP supports a JSON query parameter or `X-CalmLens-Viewer-Claims` header. Age-restricted delivery without confirmation returns `viewer/age-confirmation-required`; private access remains a separate requirement.

### Patch Changes

- 6d65133: Event facts' `url` is now a stable link that opens the item in the CalmLens portal, such as `https://calmlens.com/go/asset/<asset-id>`, in webhook payloads and the events feed. The in-memory mocks give asset facts the same links.
- e4e9894: `CalmLensMedia` shows the CDN placeholder for private assets and signed URLs too, since the CDN serves every asset's placeholder publicly. It sends only viewer claims that differ from the defaults (a `region`, or `ageConfirmed: true`), so `ageConfirmed: false` no longer makes the CDN's responses private and uncacheable, and placeholder URLs carry only the region. The mock clients serve private assets' placeholders without `assets:download`, as the CDN does.
- 1e59923: The mock clients' `cdn.serve` now sends `Cache-Control` as the CDN does: `public` only when anyone may see the asset (including a public age-restricted asset requested with `ageConfirmed`), otherwise `private`, with `max-age=31536000, immutable` for images and `max-age=3600` for other content. They previously sent `private, no-store` or `public, max-age=31536000`. PHP's `MockServerClient::decide` now also records the review in the asset's `manualReviews`, as the Rust and Java mocks already did.
- e4e9894: The mock clients accept the real client's upload timeout and response size limit: `upload_timeout` and `max_response_bytes` on Python's `MockCalmLensServerClient`, `UploadTimeout` and `MaxResponseBytes` on Go's `calmlenstest.Options`, `uploadTimeout` and `maxResponseBytes` on PHP's `MockServerClient`, and `MockOptions::upload_timeout` and `MockOptions::max_response_bytes` in Rust. They are validated like the real client's, and the size limit applies to the mock's answers.
- 91cd4a1: The `MockServerClient` in-memory API answers with the HTTP statuses the API sends: `201 Created` for `folders->create`, and `200` with an empty JSON object for asset and folder deletes (it answered `200` for creates and `204 No Content` for deletes).
- 92bf5db: `MockServerClient` runs the API's keyword search: `assets->search` matches every word of the query in any searchable field and returns the API's scores, matched fields and ranking. Mock list filters accept parentheses, with `;` binding tighter than `,`, and list cursors resume after the last item returned, so assets created or deleted between pages are neither repeated nor skipped. The default mock clock gives assets created in a row increasing `createdAt`.
- 958be0d: Creating a signed URL now fails with `sdk/invalid-argument` before sending anything when the API would reject it: a resource other than `original` or `rendered` (a placeholder needs no signed URL), a lens or transform on the `original` resource, or a lifetime that is not a whole number of seconds from 1 to 86400 (24 hours). The longest lifetime is available as `MAX_SIGNED_URL_SECONDS` in Rust and Java, `MaxSignedURLSeconds` in Go, `CalmLens::Assets::MAX_SIGNED_URL_SECONDS` in Ruby and `CalmLens\Assets::MAX_SIGNED_URL_SECONDS` in PHP.

## 0.1.0 (pre-release)

### New

- PHP client for moderation, streaming uploads, asset and folder management, events, CDN delivery, named lenses, signed URLs and browser upload tokens.
- Hash lists (`hashLists`) of PDQ hashes that image uploads are compared with: create, update and delete lists, and add hashes directly or from an image asset. The mock CalmLens keeps hash lists and their entries in memory.
- Moderation statuses (`pending`, `allowed`, `age-restricted`, `blocked`, `purged`), with `waitForDecision` returning once an asset is decided.
- CDN URLs with the `ageConfirmed` option for public age-restricted assets, and the `placeholder` resource.
- Webhook verification, offline request testing and an in-memory mock CalmLens with moderation outcomes.
- Laravel comment moderation and webhook example, and the Chirp short-post example.
