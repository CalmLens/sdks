`MockCalmLensServerClient` and `MockCalmLensAppClient` take `mockOptions.moderate`, which replaces `queuedOutcome` and `analyzedOutcome`: a function that receives each asset the mock moderates with its content (`bytes`, and `text` for a plain-text upload), the trigger (`upload`, `retry`, `rerun` or `complete`) and whether the work is queued, and returns a status or a decision built with the new `mockDecision(status)`. `flag(category, score, qualifiers?)` and `notEvaluated(category)` record findings, and a decided asset gets a complete report: every category, the highest score and the policy's actions and `flaggedCategories`. `completeProcessing(assetId, decision?)` finishes a pending asset as moderation would. Uploads now add `asset.uploaded`, `asset.classified` and automated `asset.<status>` or `asset.failed` events to the events feed. `failNextRequest` takes `details` and `retryAfter` for API errors, and each queued failure fails one request, so retries can succeed. `clearCalls()` forgets recorded requests. `enqueueEvent` now resolves to the event, which carries the asset's snapshot when it names a stored asset, and `decide` refuses `pending` and `failed`.
