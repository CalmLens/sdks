`MockServerClient` takes a `moderate` callable, which replaces `queuedOutcome` and `analyzedOutcome`: it receives a `MockModerationInput` for each asset the mock moderates, with the asset, its `bytes`, its `text` for a plain-text upload, the trigger (`upload`, `retry`, `rerun` or `complete`) and whether the work is `queued`, and returns a status or a decision built with the new `MockDecision::of($status)`. `flag($category, $score, $qualifiers)` and `notEvaluated($category)` record findings, and a decided asset gets a complete report: every category, the highest score and the policy's actions and `flaggedCategories`. `completeProcessing($assetId, $decision)` finishes a pending asset as moderation would. Uploads now add `asset.uploaded`, `asset.classified` and automated `asset.<status>` or `asset.failed` events to the events feed. `failNextRequest` takes `details` and `retryAfter` for API errors, refuses an unknown `operation`, and each queued failure fails one request, so retries can succeed. `requests()` on `MockServerClient` and `MockTransport` returns `RecordedRequest` objects with the method, the path relative to the base URL, the decoded query, the response status and the PSR-7 request, and `clearRequests()` forgets them. `decide` refuses `pending` and `failed`.
